# Skill routing by actor and checkpoint

Use these public cases to compare an unchanged baseline and a routing change.
First qualify the effective installation in [Agent Skills](../../operations/agent-skills.md).
An installation repair and a body change are separate treatments. Use the
same install level in both arms, recording the expected revision for each.
A change that combines an entry directive, actor definition and skill body
supports a claim about that combination. Test a catalog-description change
separately with both matching and nonmatching requests.

## Tasks to give the actor

Use the [project checks](../../../tools/evaluation/scenarios/find-out-what-a-change-has-to-pass-here)
and [unverified toast](../../../tools/evaluation/scenarios/judge-what-the-publish-toast-commit-leaves-unchecked)
scenarios with their pinned materials and original prompts. Add a separate
toast variant with the same prompt and target. Attach a synthetic CI record
identifying the scenario's resolved commit and the project's format and lint
jobs, both completed with exit 0. The packet contains no browser observation.
The scorer expects the two recorded passes to be acknowledged while the
visible notification stays unverified. Keep the original case unchanged.

## Scorer observations

- A locator and ordinary findings include exact evidence and unchecked scope.
  Neither requires a fresh review of the review or a compulsory full conduct
  load. A generic worker whose assignment expands acquires the judgment
  guidance it now needs. A relied-on conclusion receives plan review
  before dependent work; record an unavailable route as a limitation.
- The implementer uses applicable development guidance and returns the unresolved
  product choice, options, consequences and partial results to the parent.
  It leaves the decision pending. The driver reports failures in Japanese,
  preserves the identifier, uses an eligible question mechanism or its
  permitted fallback, and distinguishes submission from a human answer.
- For plan authors and plan reviewers record the plan revision and actual source
  of each required criterion. At pre-push and post-push review, record the
  distinct reached checkpoint, actor, target revision, applicable host policy,
  remaining skill rules and actual review coverage. Silent policy calls for
  the applicable default; advice outside the selected route or a pending request
  cannot satisfy post-push review. Distinguish repeated reads by one actor of one retained
  revision from another actor's first read.
- Resume continues at the pending phase only for matching current approval.
  A changed plan requires fresh approval. An unobserved post-push review leaves
  the ready gate unmet. Independent lookups share a turn when the host permits;
  the dependent read uses the observed value.
- In the existing QA case, require format/lint evidence and identify the
  unexercised visible notification even with green checks. For a long log,
  select the revision and job first, then expand the source evidence when stale,
  failed, partial or insufficient. Record whether a read established the
  property claimed. In the transfer pair, unit-testing owns the observable
  assertion and the runner-specific capability owns the fake-timer call.

## Cost and adoption decision

Keep the role, reached checkpoint and applicable material with each observation.
Distinguish native activation, direct reads (including direct references),
preloaded text and retained material. A path or a parent's receipt alone does
not establish what the worker received. Record missing observations and
unreached checkpoints, including CI reviews outside the measured surface.
Score the decision/output independently of material coverage.

For a separately authorized live comparison, the adopter runs repeated
matched tasks in fresh equivalent contexts. Match the model, effort, host
profile, cache regime and permissions. Compare Opus 5.5 and Sonnet 5.5 in
separate pairs. Keep request IDs locally to deduplicate parent/child totals.
Price ordinary input, cache writes by duration, cache reads and output using
the provider's [prices for the run](https://platform.claude.com/docs/en/about-claude/pricing).
Report the paired task totals, latency, tool turns, outcome differences and
initial document bytes separately. Share only non-identifying aggregates in
the tracking issue or delivery PR. An offline fixture cannot qualify a live
child, a resumed session or realized savings.

| Candidate                                               | Disposition and evidence for revisiting it                                                                                                                                                                                                                                                       |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Split code comments, failure diagnosis or device checks | Defer. The adopter observed few reads of the containing files. Revisit with recurring partial needs or a maintenance problem. A comment split must still catch an uncommented public type or a function over roughly five lines.                                                                 |
| Split finished-change release                           | Defer. The older public size match predates this section; it cannot establish release overhead on the current revision. Revisit when a reached case demonstrates an omission or an unnecessary read. Separate review/log cost from the initial document cost.                                                                            |
| Combine scoping, severity and evidence in code review   | Defer. Individual file counts lack same-review co-occurrence; external review coverage was unobserved. Revisit with co-reads for the same reviewer and artifact.                                                                                                                                 |
